# 02 · 功能点拆分

> 本文以原型实际页面和最新确认的页面权限为准：管理员使用“事项跟踪 + 成员管理”并完整管理；成员使用“成员个人页 + 只读事项跟踪”，没有成员管理页。成员只能在个人页更新负责任务的进度、编辑完整详情并管理小任务。

## 1. 功能地图

```text
ZTask
├─ 管理员 Web UI
│  ├─ F1 应用壳与局域网状态
│  ├─ F2 任务夹树
│  ├─ F3 任务列表与只读任务卡
│  ├─ F4 任务编辑浮窗与小任务
│  ├─ F5 成员管理、分享链接与网络配置
│  ├─ F6 情况看板：成员筛选与统计
│  ├─ F7 预计完成时间分布
│  └─ F8 时间段进展变化与 diff
├─ 成员链接 Web UI
│  ├─ F9 分享链接落地、会话恢复与失效页
│  ├─ F10 成员个人页：我负责的 / 我协作的
│  ├─ F11 负责人更新进度/完整详情并管理小任务（仅个人页）
│  └─ F12 只读事项跟踪：相关任务、看板与历史
└─ 横切能力
   ├─ F13 服务端身份、页面权限与数据隔离
   ├─ F14 本地文件持久化、历史与并发控制
   └─ F15 深链、空态、错误态与可访问性
```

## 2. 角色与页面能力矩阵

| 能力 | 管理员 | 成员个人页：负责人 | 成员个人页：协作人 | 成员事项跟踪 |
| --- | --- | --- | --- | --- |
| 查看自己相关任务 | 全部任务 | 是 | 是 | 是，只读 |
| 查看情况看板与历史 diff | 全部范围 | 不提供于个人页 | 不提供于个人页 | 是，仅相关范围 |
| 修改任务进度 | 是 | **是，仅自己负责的主任务** | 否 | **否，包括自己的任务** |
| 编辑完整任务进展详情 | 是 | **是，仅自己负责的主任务** | 否 | **否** |
| 新建/编辑/删除小任务 | 是 | **是，仅自己负责主任务下的小任务** | 否 | **否** |
| 修改描述、成员、重要度、预计完成 | 是 | 否 | 否 | 否 |
| 新建/删除任务夹和主任务 | 是 | 否 | 否 | 否 |
| 打开任务详情 | 可编辑 | 卡片内直接展示 | 只读 | 只读浮窗 |
| 访问成员管理 | 完整管理 | **无此页面** | **无此页面** | 不适用 |
| 管理分享链接和网络 | 是 | 否 | 否 | 否 |

owner/collaborator 同时决定任务可见范围与个人页写权限。成员写权限只覆盖主任务 progress、完整 detailText 和其小任务的新建/编辑/删除；主任务其他字段、任何任务的 owner/collaborator 分配和主任务删除仍仅管理员可操作。成员会话交换、刷新和注销是认证动作，不属于业务管理。

同一成员在同一任务只能具有一种角色，后端拒绝 owner/collaborator 重复分配。

## 3. 管理员功能明细

| ID | 功能与验收口径 | 来源 | 主要接口/数据 |
| --- | --- | --- | --- |
| F1 | 顶栏展示 ZTask、事项跟踪/成员管理、LAN 状态与管理员身份；默认仅 loopback，可动态开启具体 LAN IP | 原型 + 新决策 | network.json、NetworkService |
| F2 | 左树任务夹任意嵌套、展开/折叠、新建；选中后包含全部后代任务；树中任务可打开详情 | 文字 + 原型 | folder/task JSON + 内存树索引 |
| F3 | 任务管理 tab 支持增删改查、重要度筛选和描述搜索；只读卡展示完整字段、小任务和进展 | 文字 + 原型 | 任务列表查询 |
| F4 | 点击标题或双击卡片打开可编辑浮窗；小任务只能一层；删除有确认 | 文字 + 原型 | editor API、version |
| F5 | 成员添加/编辑/归档、计数；链接生成/复制/重置/吊销；网络分享启停 | 文字 + 原型补充 | member/share-link/network JSON |
| F6 | 看板成员多选，不选表示整体；统计已完成、51–99%、0–50% 及重要度分布 | 文字 + 原型 | current 聚合统计 |
| F7 | 点击统计卡展开预计完成时间堆叠柱状图 | 原型补充 | dashboard distribution |
| F8 | 默认昨天至今、自定义起止日；展示进度前后值、详情 diff、单条及批量展开/折叠 | 原型补充 | revisions.jsonl、as-of 查询 |

### 3.1 任务字段口径

| 字段 | 主任务 | 小任务 | 规则 |
| --- | --- | --- | --- |
| 任务描述 | 有 | 有 | 去空白后必填并设长度上限 |
| 负责人 | 多个 | 原型 UI 为单个 | 决定可见范围与个人页主任务写权限 |
| 协作人员 | 多个 | 原型未展示 | 决定可见范围；协作只读 |
| 进度 | 0–100 | 0–100 | 整数；父子独立，不自动平均 |
| 进展详情 | 多行文本 | 原型未展示 | 管理员与主任务负责人均可编辑完整当前详情，历史 revision 不可改 |
| 重要度 | 高/中/低 | 高/中/低 | high/mid/low |
| 预计完成时间 | 日期 | 日期 | date-only；是否允许为空待确认 |
| 所在任务夹 | 有 | 继承父任务 | 小任务不能独立移动 |
| 父任务 | 无 | 有且仅一个 | 聚合 schema 与 service 防第三层 |

### 3.2 任务列表与编辑

- 选中父任务夹时聚合所有后代主任务，小任务跟随主任务显示，不重复计数。
- 列表为统一只读卡；管理员通过浮窗编辑，筛选和搜索不改变看板筛选。
- 浮窗通过同一聚合写协议保存主任务、分配和小任务，冲突时保留草稿。
- 推荐软删除：普通树和看板隐藏，历史 revision 保留；删除主任务包含整个小任务组。

### 3.3 成员、链接与网络管理

- 姓名必填，角色默认“成员”，颜色稳定分配；负责/协作计数只统计未完成主任务。
- 推荐移除实现为归档：立即吊销链接与会话；任务保留 assignment ID，但 active 查询视为无效分配并显示待分配。
- 成员管理页提供局域网分享控制区：列出本机可选 IP，支持开启、切换和关闭监听，展示 running/degraded/offline 与 shareBaseUrl。
- 生成链接前若分享未开启，先引导开启；不能分发不可达的 127.0.0.1 URL。
- 切换 IP 不重写 token，但新 URL 需重新分发；hash-only 与随时复制的取舍见 [09 §2](09-review-guide.md#2-访问决策与待确认问题)。

## 4. 成员个人页（原型“成员链接 · 某某”）

### 4.1 页面结构

- 顶栏显示 ZTask 成员视图、当前成员姓名与链接状态，不显示管理员身份或成员管理导航。
- “我负责的任务”和“我协作的任务”分组展示；计数只统计当前 memberId 相关主任务。
- 每张卡显示任务路径、重要度、负责人、协作人、预计完成、小任务摘要、当前进度和完整详情。
- 页面导航只有“成员个人页”和“事项跟踪”，没有成员管理、链接管理或网络配置。

### 4.2 我负责的：进度、详情与小任务管理

- 进度滑块只修改本地草稿，必须点击“保存进度”并成功后生效。
- 进展详情可以编辑完整当前文本，通过独立“保存详情”提交；不再限制为只能追加。
- 历史 revision 仍不可修改或删除；编辑当前详情会追加一份新的完整快照，因此时间段 diff 不受影响。
- 可以在负责的主任务下新建、编辑、删除小任务，不能继续创建第三层任务；小任务可编辑描述、进度、重要度和预计完成时间；新建时默认当前成员为单 owner，成员不能修改任何任务的 owner/collaborator。
- 进度、详情和小任务写操作都携带聚合 version；冲突时保留草稿并提示刷新。
- 不能修改主任务描述、owners/collaborators、重要度、预计完成时间、folderId、parentId、任何任务分配，也不能删除主任务或新建顶级任务。

### 4.3 我协作的：只读

- 展示与个人页负责的卡片相同的信息，但进度、详情和小任务管理控件禁用或不渲染。
- 服务端同样拒绝 collaborator 的写请求，不能依赖前端禁用。

## 5. 成员只读事项跟踪

- 与管理员事项跟踪同构，包含任务管理和情况看板两个 tab，但所有任务字段与操作只读。
- 数据仍限 owner/collaborator 相关任务；左树只返回含可见任务的任务夹及祖先，计数按可见范围。
- 任务卡、树任务和详情浮窗只读；即使是自己负责的任务，也不能在此页面修改进度或详情。
- 不显示新建任务夹、新建任务、编辑、删除、添加小任务、进度滑块、详情追加或保存按钮。
- 情况看板与历史 diff 只在相关任务集合中查询；筛选为空表示“我的相关任务整体”，不是全团队整体。
- 查询、筛选、展开统计图和 diff 是只读交互，不属于业务修改。

## 6. 链接落地与失效

- URL 采用 `/#/s/<token>`；交换成功后清除 secret，进入成员个人页 `/#/s/home`，可切换 `/#/s/tracker`。
- 失效链接统一提示，不区分猜错、重置或吊销；成员 401 清理私有 query cache 后进入失效页。
- 不提供 `/share/members` 团队目录或 `/#/s/members` 页面；任务卡仅包含完成协作所需的成员摘要。

## 7. 看板业务口径

1. 管理员先取当前任务夹及后代；成员先取相关任务，再与当前可见任务夹范围求交。
2. 默认只统计主任务，小任务不重复计数。
3. 管理员不选成员 = 全部；成员不选 = 自己相关任务整体。
4. 选择成员后只统计所选成员为 owner 的任务，多成员为 OR；筛选只能缩小范围。
5. 三桶互斥：done=100、gt50=51–99、lt50=0–50。
6. 时间分布按 manifest 时区今天计算；dueDate=null 若允许需独立未排期桶。
7. 历史窗口为 [start,end)，before/after 分别取 <start/<end 的最后完整快照；成员更新与管理员更新都进入同一 revision 协议。
8. 历史候选包含软删除任务，响应带 currentlyDeleted；当前已删除项必须显示“当前已删除”徽章并固定排在非删除项之后，created-then-deleted 以 deleted 为主状态。

## 8. 横切状态与验收

| 场景 | 期望 |
| --- | --- |
| 首次启动 | 默认仅 loopback，自动创建文件结构并显示空态 |
| 开启分享 | 动态启动具体 LAN IP，生成使用 shareBaseUrl 的链接 |
| A 猜测 B 的任务 ID | 404，不确认任务存在或返回内容 |
| A 调用管理员 API | 403，不因知道 URL 获得权限 |
| owner 在个人页保存进度/完整详情或管理小任务 | 服务端验证 owner，写 current + 完整 revision，actor=member |
| owner 尝试在事项跟踪修改 | 无控件，也没有该页面专用写入口 |
| collaborator 写进度/详情 | 403，文件与 revision 不变化 |
| 成员访问成员管理路由 | 无页面；管理员 API 仍拒绝 |
| 两人同时保存 | 一个 version 成功，另一个 409 并保留草稿 |
| 链接重置/吊销 | 旧链接和会话失效，新链接按当前 shareBaseUrl 生成 |

## 9. 首版明确不做

- 成员管理页面向成员开放，或成员修改个人资料/他人资料。
- 成员在事项跟踪中编辑任何任务，或修改主任务其他字段、分配、删除主任务和新建顶级任务。
- 成员修改或删除历史 revision；个人页只能编辑当前详情并追加新快照。
- 任务夹拖拽、批量编辑、回收站、三层任务、自动汇总父进度。
- 成员账号密码、附件、评论、提醒、公网分享和多服务实时事件总线。
