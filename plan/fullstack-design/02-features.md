# 02 · 功能点拆分

> 本文以原型实际页面和最新确认的页面权限为准：管理员使用“事项跟踪 + 成员管理”并完整管理；成员使用“成员个人页 + 只读事项跟踪”，没有成员管理页。成员可以查看团队全部任务，但只能在个人页更新负责任务的进度、编辑完整详情并管理小任务。管理员权限是成员记录上的能力位：拥有它的成员通过分享链接进入管理员页面，获得与管理员相同的页面与操作范围。

## 1. 功能地图

```text
ZTask
├─ 管理员 Web UI
│  ├─ F1 应用壳与局域网状态
│  ├─ F2 任务夹树
│  ├─ F3 任务列表与只读任务卡
│  ├─ F4 任务编辑浮窗与小任务
│  ├─ F5 成员管理、分享链接与网络配置
│  ├─ F6 情况看板：成员筛选与统计
│  ├─ F7 预计完成时间分布
│  └─ F8 时间段进展变化与 diff
├─ 成员链接 Web UI
│  ├─ F9 分享链接落地、会话恢复与失效页
│  ├─ F10 成员个人页：我负责的 / 我协作的 / 其他成员的任务
│  ├─ F11 负责人更新进度/完整详情并管理小任务（仅个人页）
│  └─ F12 只读事项跟踪：团队全部任务、看板与历史
└─ 横切能力
   ├─ F13 服务端身份、页面权限与数据隔离
   ├─ F14 本地 SQLite 持久化、历史与并发控制
   └─ F15 深链、空态、错误态与可访问性
```

## 2. 角色与页面能力矩阵

| 能力 | 管理员 | 成员个人页：负责人 | 成员个人页：协作人 | 成员事项跟踪 |
| --- | --- | --- | --- | --- |
| 查看团队全部任务 | 全部任务 | 是，分三组展示 | 是，分三组展示 | 是，只读 |
| 查看情况看板与历史 diff | 全部范围 | 不提供于个人页 | 不提供于个人页 | 是，团队全部范围 |
| 修改任务进度 | 是 | **是，仅自己负责的主任务** | 否 | **否，包括自己的任务** |
| 编辑完整任务进展详情 | 是 | **是，仅自己负责的主任务** | 否 | **否** |
| 新建/编辑/删除小任务 | 是 | **是，仅自己负责主任务下的小任务** | 否 | **否** |
| 修改描述、成员、重要度、预计完成 | 是 | 否 | 否 | 否 |
| 新建/删除任务夹和主任务 | 是 | 否 | 否 | 否 |
| 打开任务详情 | 可编辑 | 卡片内直接展示 | 只读 | 只读浮窗 |
| 访问成员管理 | 完整管理 | **无此页面** | **无此页面** | 不适用 |
| 管理分享链接和网络 | 是 | 否 | 否 | 否 |

任务数据全员可见；owner 决定个人页分组与写权限，collaborator 只读。成员写权限只覆盖主任务 progress、完整 detailText 和其小任务的新建/编辑/删除；主任务其他字段、任何任务的 owner/collaborator 分配和主任务删除仍仅管理员可操作。成员会话交换、刷新和注销是认证动作，不属于业务管理。管理员成员登录后使用上表“管理员”列；其分享链接直接落地管理页。

同一成员在同一任务只能具有一种角色，后端拒绝 owner/collaborator 重复分配。

## 3. 管理员功能明细

| ID | 功能与验收口径 | 来源 | 主要接口/数据 |
| --- | --- | --- | --- |
| F1 | 顶栏展示 ZTask、事项跟踪/成员管理、LAN 状态与管理员身份；默认仅 loopback，可动态开启具体 LAN IP | 原型 + 新决策 | network_config、NetworkService |
| F2 | 左树任务夹任意嵌套、展开/折叠、新建；选中后包含全部后代任务；树中任务可打开详情 | 文字 + 原型 | folders/tasks 表 + SQL 树查询 |
| F3 | 任务管理 tab 支持增删改查、重要度筛选、负责人多选筛选和描述搜索；只读卡展示完整字段、小任务和进展 | 文字 + 原型 | 任务列表查询 |
| F4 | 点击标题或双击卡片打开可编辑浮窗；小任务只能一层；删除有确认 | 文字 + 原型 | editor API、version |
| F5 | 成员添加/编辑/归档、计数；链接生成/复制/重置/吊销；网络分享启停 | 文字 + 原型补充 | members/share_links/network_config 表 |
| F6 | 看板成员多选，不选表示整体；统计已完成、51–99%、0–50% 及重要度分布 | 文字 + 原型 | SQL 聚合统计 |
| F7 | 点击统计卡展开预计完成时间堆叠柱状图 | 原型补充 | dashboard distribution |
| F8 | 默认昨天至今、自定义起止日；展示进度前后值、详情 diff、单条及批量展开/折叠 | 原型补充 | task_revisions、as-of 查询 |

### 3.1 任务字段口径

| 字段 | 主任务 | 小任务 | 规则 |
| --- | --- | --- | --- |
| 任务描述 | 有 | 有 | 去空白后必填并设长度上限 |
| 负责人 | 多个 | 原型 UI 为单个 | 决定个人页分组与主任务写权限；数据本身全员可见 |
| 协作人员 | 多个 | 原型未展示 | 决定个人页分组；协作只读 |
| 进度 | 0–100 | 0–100 | 整数；父子独立，不自动平均 |
| 进展详情 | 多行文本 | 原型未展示 | 管理员与主任务负责人均可编辑完整当前详情，历史 revision 不可改 |
| 方案描述 | 选填多行文本 | 无 | m18-01：记录实现思路/技术选型/拆解方案；随任务浮窗保存，任务卡「方案」区展示，空时显示「未填写方案（选填）」 |
| 重要度 | 高/中/低 | 高/中/低 | high/mid/low |
| 预计完成时间 | 日期 | 日期 | date-only；是否允许为空待确认 |
| 所在任务夹 | 有 | 继承父任务 | 小任务不能独立移动 |
| 父任务 | 无 | 有且仅一个 | 聚合 schema 与 service 防第三层 |

### 3.2 任务列表与编辑

- 选中父任务夹时聚合所有后代主任务，小任务跟随主任务显示，不重复计数。
- 列表为统一只读卡；管理员通过浮窗编辑，筛选和搜索不改变看板筛选。
- 负责人筛选位于重要度右侧、搜索框左侧，支持搜索成员、多选和清除；选中成员之间为 OR，并与重要度、描述搜索取 AND。
- 负责人命中分两种：主任务负责人命中时保留整条任务及全部子任务；只有子任务负责人命中时保留主任务，但只返回命中的子任务，卡片标注“已按负责人筛选”，完成数按可见子任务计算。
- 描述搜索只匹配主任务描述；负责人筛选不改变任务树计数、看板统计和成员视图。
- 浮窗通过同一聚合写协议保存主任务、分配和小任务，冲突时保留草稿。
- 推荐软删除：普通树和看板隐藏，历史 revision 保留；删除主任务包含整个小任务组。

### 3.3 成员、链接与网络管理

- 姓名必填，角色默认“成员”，颜色稳定分配；负责/协作计数只统计未完成主任务。
- 推荐移除实现为归档：立即吊销链接与会话；任务保留 assignment ID，但 active 查询视为无效分配并显示待分配。
- 成员管理页提供局域网分享控制区：列出本机可选 IP，支持开启、切换和关闭监听，展示 running/degraded/offline 与 shareBaseUrl。
- 生成链接前若分享未开启，先引导开启；不能分发不可达的 127.0.0.1 URL。
- 切换 IP 不重写 token，但新 URL 需重新分发；hash-only 与随时复制的取舍见 [09 §2](09-review-guide.md#2-访问决策与待确认问题)。

## 4. 成员个人页（原型“成员链接 · 某某”）

### 4.1 页面结构

- 顶栏显示 ZTask 成员视图、当前成员姓名与链接状态，不显示管理员身份或成员管理导航。
- 三组展示团队全部事项：“我负责的任务”“我协作的任务”“其他成员的任务”；计数分别按当前 memberId 的主任务 owner、collaborator 和其余任务统计，三组不重不漏。
- 每张卡显示任务路径、重要度、负责人、协作人、预计完成、小任务摘要、当前进度和完整详情。
- 三组标题默认为展开；点击标题可折叠/展开该组，折叠后保留标题与计数，再点恢复。标题是带 `aria-expanded` 的按钮，支持键盘 Enter / Space。
- 页面导航只有“成员个人页”和“事项跟踪”，没有成员管理、链接管理或网络配置。

### 4.2 我负责的：进度、详情与小任务管理

- 进度与完整进展详情共用一个“保存”按钮：一次提交本任务的全部修改，先写进度、再用响应里的新 version 写详情。
- 编辑后停顿 2 秒自动保存；页面级 Ctrl+S 保存整页所有 owner 任务的草稿。底部内联显示保存状态与时间。
- 进展详情可以编辑完整当前文本，不再限制为只能追加。历史 revision 仍不可修改或删除；每次实际提交会追加一份新的完整快照，因此时间段 diff 不受影响。
- 可以在负责的主任务下新建、编辑、删除小任务，不能继续创建第三层任务；小任务可编辑描述、进度、重要度和预计完成时间；新建时默认当前成员为单 owner，成员不能修改任何任务的 owner/collaborator。
- 进度、详情和小任务写操作都携带聚合 version；冲突时保留草稿并提示刷新。
- 不能修改主任务描述、owners/collaborators、重要度、预计完成时间、folderId、parentId、任何任务分配，也不能删除主任务或新建顶级任务。

### 4.3 我协作的 / 其他成员的任务：只读

- 两组都展示与负责卡相同的信息，但进度、详情和小任务管理控件禁用或不渲染；其他成员任务标“其他成员 · 只读”。
- 服务端同样拒绝 collaborator、仅小任务被分配者和其他成员的写请求，不能依赖前端禁用。

## 5. 成员只读事项跟踪

- 与管理员事项跟踪同构，包含任务管理和情况看板两个 tab，但所有任务字段与操作只读。
- 数据包含团队全部任务；左树保留完整任务夹（含空夹）与管理端同构，计数为团队任务数。
- 任务卡、树任务和详情浮窗只读；即使是自己负责的任务，也不能在此页面修改进度或详情。
- 不显示新建任务夹、新建任务、编辑、删除、添加小任务、进度滑块、详情追加或保存按钮。
- 情况看板与历史 diff 查询团队全部任务；筛选为空表示“团队整体”，`memberIds` 只按 owner 缩小。
- 查询、筛选、展开统计图和 diff 是只读交互，不属于业务修改。

## 6. 链接落地与失效

- URL 采用 `/#/s/<token>`；交换成功后清除 secret，进入成员个人页 `/#/s/home`，可切换 `/#/s/tracker`。
- 失效链接统一提示，不区分猜错、重置或吊销；成员 401 清理私有 query cache 后进入失效页。
- 不提供 `/share/members` 团队目录或 `/#/s/members` 页面；任务卡仅包含完成协作所需的成员摘要。

## 7. 看板业务口径

1. 管理员与成员都取当前任务夹及后代，直接覆盖团队全部任务。
2. 默认只统计主任务，小任务不重复计数。
3. 管理员与成员不选成员 = 全部团队任务。
4. 选择成员后只统计所选成员为 owner 的任务，多成员为 OR；筛选是合法缩小，不再是可见范围校验。
5. 任务管理的负责人筛选与看板成员筛选是两个独立入口：前者同时考虑主任务和子任务负责人并裁剪子任务，后者只按主任务 owner 统计且不改变任务卡内容；两者不能互相复用命中集合。
6. 三桶互斥：done=100、gt50=51–99、lt50=0–50。
7. 时间分布按 `meta.time_zone` 的今天计算；dueDate=null 的主任务不进入分布。
8. 历史窗口为 [start,end)，before/after 分别取 <start/<end 的最后完整快照；成员更新与管理员更新都进入同一 revision 协议。
9. 历史候选包含软删除任务，响应带 currentlyDeleted；当前已删除项必须显示“当前已删除”徽章并固定排在非删除项之后，created-then-deleted 以 deleted 为主状态。

## 8. 横切状态与验收

| 场景 | 期望 |
| --- | --- |
| 首次启动 | 默认仅 loopback，自动创建数据库与目录并显示空态 |
| 开启分享 | 动态启动具体 LAN IP，生成使用 shareBaseUrl 的链接 |
| A 猜测 B 的任务 ID | 404，不确认任务存在或返回内容 |
| A 调用管理员 API | 403，不因知道 URL 获得权限 |
| owner 在个人页保存进度/完整详情或管理小任务 | 服务端验证 owner，事务写当前状态 + 完整 revision，actor=member |
| owner 尝试在事项跟踪修改 | 无控件，也没有该页面专用写入口 |
| collaborator 写进度/详情 | 403，数据库与 revision 不变化 |
| 成员访问成员管理路由 | 无页面；管理员 API 仍拒绝 |
| 两人同时保存 | 一个 version 成功，另一个 409 并保留草稿 |
| 链接重置/吊销 | 旧链接和会话失效，新链接按当前 shareBaseUrl 生成 |

## 9. 首版明确不做

- 成员管理页面向成员开放，或成员修改个人资料/他人资料。
- 成员在事项跟踪中编辑任何任务，或修改主任务其他字段、分配、删除主任务和新建顶级任务。
- 成员修改或删除历史 revision；个人页只能编辑当前详情并追加新快照。
- 任务夹拖拽、批量编辑、回收站、三层任务、自动汇总父进度。
- 成员账号密码、附件、评论、提醒、公网分享和多服务实时事件总线。
