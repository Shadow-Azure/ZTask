# Agent Note: 冒烟修复的创建原子性与浮窗生命周期

Status: implemented

[English](2026-11-03-smoke-create-dialog-network-fixes.en.md) | 中文

## Problem

真实 GUI 冒烟发现三处回归：新建任务浮窗收集的小任务会被 POST 静默丢弃；任务删除成功后确认浮窗残留并挡住看板切换；局域网分享在运行中初始化过面板时，关闭再开启会沿用旧 LAN 端口而不是服务实际 loopback 端口。前一个问题直接造成用户输入丢失，后两个问题让成功操作后的界面和地址给出错误事实。

## Decision

主任务创建 API 接受可选 `subtasks.create` 意图，并在一次聚合写入里校验字段、owner 和一层嵌套约束；任一小任务非法时整次创建不落盘。前端新建浮窗把小任务草稿随主任务一起提交。删除 mutation 成功后先复位确认态再关闭编辑器。局域网分享关闭成功后显式把端口表单重置为当前 `loopbackUrl` 的端口，避免依赖一个不会因关闭而变化的 watcher。

## Alternatives considered

前端先建主任务再逐个建小任务被放弃：这不是原子操作，中途失败会留下部分创建结果。禁止新建浮窗输入小任务也被放弃：交互原型和用户预期都要求一次录入。仅在网络查询刷新后修正端口被放弃：`loopbackUrl` 不因关闭变化，watcher 不会触发，仍会沿用旧端口。

## Consequences

`POST /admin/tasks` 的主任务分支契约扩展为可携带小任务创建意图；服务端测试固化成功映射、owner 校验和不写入边界。删除确认和分享端口由组件测试看护。未来若要支持创建时小任务批量更新或删除，需要继续扩展意图并保持同样的“全有或全无”语义。
