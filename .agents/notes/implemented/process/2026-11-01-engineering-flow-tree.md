# Agent Note: 研发流程树按可验证交付边界拆分

Status: implemented

[English](2026-11-01-engineering-flow-tree.en.md) | 中文

## Problem

原型与全栈设计完成后，需要把大量前后端能力拆成可独立验收的工作单元，同时继承 StudyWiki 已验证的流程门禁，避免仅凭页面或技术层拆分造成权限、恢复与历史能力延期。

## Decision

保留 M1 设计历史，新增 M2 可运行基座、M3 管理端任务闭环、M4 分享与成员协作、M5 看板历史与交付加固，共 12 个 issue。按端到端能力组织里程碑，在所属阶段同步交付权限、版本和文件恢复约束，而不是把所有横切风险堆到最后。同步 StudyWiki 当前流程脚本、独立测试和 skills；新对象未同步 GitHub，故全部保持 backlog。

## Alternatives considered

- 按前端、后端、存储分别建里程碑：接口需要跨阶段等待，无法尽早验证主链路，否决。
- 每个 API 或页面建一个 issue：数量过大且验收碎片化，合并为可独立走查的能力单元。
- 立即调用 `flow:sync`：本次只规划本地流程树，不创建远端对象，否决。

## Consequences

后续实现可从 M2 的同源服务、文件协议和共享壳开始，逐阶段得到可运行的产品闭环。开工前必须同步 GitHub 编号并流转 issue；若设计中的待确认项改变接口，应先修订设计和对应 issue，而不是在实施中静默偏离。
