# Agent Note: 成员个人页自动保存与整页保存

Status: implemented

[English](2026-11-08-member-auto-save.en.md) | 中文

## Problem

成员个人页的「我负责的」卡片原来用「保存进度」「保存详情」两个按钮分别提交进度与完整详情。用户反馈只改进度详情时不确定该点哪个按钮，且当进度不变时保存动作容易被按钮的禁用状态卡住。两个按钮也意味着同一张卡的两类修改无法一次提交，低频使用者必须理解两条独立写路径。成员页保存交互以本决策与确认后的实现为准；m1-01 原型同时承载其他 UI 迭代。

## Decision

每张 owner 任务卡只保留一个「保存」：提交本任务的全部修改，先 PATCH progress，再用响应里的新 version PATCH detail；两个端点仍独立，但由前端串行提交，避免同一聚合 version 被并发写。编辑后停顿 2 秒自动保存同一套草稿，状态内联显示「等待自动保存 / 正在保存 / 已保存 / 失败」及保存时间；成功后把响应写回 share home 缓存，卡片立即前进到新 version。成员首页监听 Ctrl/⌘+S，遍历所有 owner 卡调用各自的保存并提示整页结果。409 仍保留草稿并展示「放弃草稿并刷新」。

## Alternatives considered

未保留两个保存按钮：它要求用户判断改动属于哪条写路径，正是本次问题的来源。未只做自动保存：用户仍需要立即提交的确定性动作，因此保留单卡「保存」并增加整页 Ctrl+S。未把两个端点合并成新的后端原子接口：这会扩大 API 与 revision 语义的改动面，前端串行提交已满足一次操作保存全部修改。未在详情 blur 时保存：停顿自动保存对键盘和滑块的交互更一致。自动保存每次停顿都会追加一份详情快照；通过 2 秒去抖和保存中继续输入重新计时控制频率，未引入后端快照合并。

## Consequences

- 成员卡保存交互只剩一个显式按钮，进度与详情一起提交；Ctrl+S 保存整页。
- 自动保存在组件卸载时清理定时器；保存失败不自动重试，等下一次输入或手动保存。
- 冲突处理沿用现有 409 草稿保留与刷新提示；小任务编辑器仍有自己的保存按钮，Ctrl+S 不提交未确认的小任务表单。
- 测试覆盖：只改进度、只改详情、进度+详情串行 version、2 秒自动保存、Ctrl+S 整页保存、409 冲突。
