# Agent Note: 任务管理原型负责人多选筛选

Status: implemented

[English](2026-11-03-assignee-multiselect-filter.en.md) | 中文

## Problem

[m1-01 原型](../../../../plan/m1-01-ui-prototype/ztask-prototype.html)的任务管理只能按重要度和关键词搜索筛选，无法按负责人定位。负责人同时挂在主任务与子任务上：只按主任务负责人过滤会漏掉“子任务由我负责”的任务，只按子任务负责人过滤又会把主任务错误隐藏。筛选还需要与既有重要度、搜索条件同时生效，否则用户无法组合缩小范围。

## Decision

工具栏新增负责人多选下拉，选中成员之间取并集。每个任务先按主任务负责人判断：任一选中成员是主任务负责人时，保留整条任务及全部子任务，子任务负责人不参与裁剪；否则只保留负责人属于选中集合的子任务，主任务本身继续展示，卡片内注明“已按负责人筛选，仅显示所选负责人负责的子任务”。子任务完成数按当前可见子任务计算。负责人筛选与重要度、关键词搜索取交集，搜索仍只匹配主任务描述。匹配逻辑抽成纯函数 `taskAssigneeMatch`，由规格测试覆盖主任务命中、仅子任务命中、未命中、空选择和多选并集。为演示“子任务负责人不是主任务负责人”的分支，原型示例数据把「任务树组件重构」的「大数据量虚拟滚动」子任务负责人改为赵敏。

## Alternatives considered

未采用“主任务负责人”和“子任务负责人”两个独立筛选器，因为同一批成员被拆成两个入口，用户需要理解两套语义才能查全；未采用只隐藏不匹配子任务、仍显示所有主任务的做法，因为主任务没有任何匹配子任务时会出现空卡片；未把搜索扩展到子任务描述，因为这会改变既有搜索语义并引入“仅子任务命中时是否裁剪”的额外规则，超出本次筛选需求；未直接实现到 `apps/web`，因为本次交付只要求原型与截图，真实实现需要服务端查询能力配合。

## Consequences

原型现在可以按负责人多选筛选，并在主任务负责人命中时展示完整任务、仅子任务负责人命中时展示子集。可见子任务的完成数会小于任务全部子任务数，卡片内的提示说明了这一差异；任务树计数与情况看板统计不受筛选影响。后续真实实现需要把相同语义下沉到查询层，并处理成员归档、无子任务任务与多负责人子任务等边界。新增 `taskAssigneeMatch` 与筛选后卡片渲染的规格测试。
