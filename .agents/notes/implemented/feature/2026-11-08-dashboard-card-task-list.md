# Agent Note: 情况看板卡片任务列表

Status: implemented

[English](2026-11-08-dashboard-card-task-list.en.md) | 中文

## Problem

[原型](../../../../plan/m1-01-ui-prototype/ztask-prototype.html)与真实看板的三统计卡只展开预计完成时间分布柱状图。用户看到「已完成 2 项」或「进行中 3 项」后，无法知道具体是哪些任务，也不能从统计直接打开任务详情；任务管理页的列表承担增删改查与筛选，不适合作为「先看统计、再看明细」的第二跳。用户要求点击卡片后在柱状图下增加简洁紧凑的分页任务列表，点击任务行打开现有任务详情浮窗，先调整原型并确认版式，再进行真实开发。

## Decision

统计卡展开的图表面板内，柱状图与 x 轴下方显示该集合的任务列表：每页 5 项，行内由重要度色点、任务描述、重要度标签、负责人头像、进度条和截止日期组成，行尾箭头提示可点击；底部显示每页条数、总项数、当前页 / 总页数和上一页/下一页按钮。列表与柱状图使用同一任务集合，卡片切换、成员筛选或任务夹变化时回到第一页；点击任务行复用现有任务详情入口：管理员打开编辑浮窗，成员域打开只读详情。空集合保留原空态，不渲染列表。

服务端复用 `scopedAggregates` 的 folder / member / share 口径，新增 `GET /admin/dashboard/tasks` 与 `GET /share/dashboard/tasks`：只返回列表展示字段，按 `createdAt,id` 稳定排序，使用与任务列表一致的 base64url opaque cursor，固定每页 5 项，并在响应里回传总数。前端用游标栈支持上一页/下一页，不在前端拼 offset；翻页查询期间用 loading 状态保护当前页，避免总数短暂为空时把页码重置。真实界面与原型版式一致，截图见 `plan/m1-01-ui-prototype/review/90–98`。

## Alternatives considered

未采用「把任务列表放进统计卡内部」的方案，因为三张卡并排时高度和宽度不足以容纳可读任务行，也会挤压重要度计数；未采用「每页 10/20 项」的方案，因为用户明确要求简洁紧凑，5 行能在柱状图下保持一屏可见；未采用「点击任务行先跳任务管理页再打开浮窗」的方案，因为多一次上下文切换，违背从统计直接看明细的目的；未采用「列表只显示任务描述」的方案，因为重要度、负责人、进度和截止日期是判断该集合构成的关键信息，去掉后仍需进入浮窗才能判断。服务端未采用「复用 `/admin/tasks` 列表」的方案，因为它不支持进度桶过滤，也会把筛选/任务卡字段带进看板；未采用「一次返回整桶任务、前端本地分页」的方案，因为大团队会放大响应体，且与仓库既有的 cursor 分页约定不一致。

## Consequences

原型数据每桶只有 1–3 项时页码显示 1/1；真实数据超过 5 项才会出现第 2 页。看板任务列表与统计卡一样 15 秒轮询，游标只描述位置；若两次刷新间任务被删除或改桶，当前页可能变短，前端在总数缩小且不在加载中时回到第一页，避免停留在空页。接口只增加只读列表，不改变任务数据协议、统计口径或成员可见范围；真实实现已补服务端/组件测试与真实应用前后截图，完整测试 476 项通过。
