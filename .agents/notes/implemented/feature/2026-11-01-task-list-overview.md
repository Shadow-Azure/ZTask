# Agent Note: 任务列表小任务与进展概览

Status: implemented

[English](2026-11-01-task-list-overview.en.md) | 中文

## Problem

[m1-01 原型](../../../../plan/m1-01-ui-prototype/ztask-prototype.html)的事项跟踪列表只显示小任务总数和首行进展，小任务又以独立表格行持续展开。用户无法在同一任务上下文里快速判断小任务完成情况和阅读完整进展，只能打开编辑浮窗。

## Decision

事项跟踪右侧改为始终展开的只读任务卡片，不再使用表格列、展开按钮、行内快捷进度或添加/删除操作。每个任务只有一个外框：标题区展示任务名、负责人、重要度、预计完成时间与总进度；内容区以同一层级的双栏展示子任务进展和完整进展详情，不嵌套小卡片；默认左侧占 36%、右侧占 64%，中间分隔条支持指针拖拽和左右方向键，范围限制为 26%–55%，所有任务卡片同步调整并在列表重绘后保留宽度。子任务以圆环进度、名称和负责人信息呈现：圆环中心显示百分比，进行中为蓝色、完成为绿色，名称下方显示负责人头像与姓名；空数据使用轻量文字。点击标题区仍可打开原编辑浮窗，所有修改集中在浮窗内；窄屏将内容区改为单栏。

## Alternatives considered

未采用右侧详情抽屉，因为当前页面已有左树和右任务板，再增加持久面板会挤压内容；未采用逐项展开的手风琴，因为用户需要直接查看所有任务进展，额外展开状态会增加操作和视觉割裂；未采用嵌套卡片与行内操作，因为它们会把统一任务对象拆成多个视觉孤岛，并混淆只读查看与编辑场景。

## Consequences

主列表现在以统一容器持续提供子任务完成度和完整进展，任务标题区是唯一进入编辑浮窗的入口。移除了列表行内快捷进度、添加与删除功能，筛选、搜索和新建任务仍保留。新增 `subtaskSummary` 与只读卡片渲染测试，浏览器验收覆盖全部内容直接可见、列表无编辑控件、浮窗打开、键盘操作、筛选和空状态。
