# Agent Note: 事项跟踪原型自动保存与树权限

Status: proposed

[English](2026-11-08-tracker-autosave-context-menu.en.md) | 中文

## Problem

[原型](../../../../plan/m1-01-ui-prototype/ztask-prototype.html)目前依赖任务浮窗的「保存」、成员浮窗的「保存」和成员视图的「保存进度」，编辑过程中没有全局的变更检测或自动保存反馈。左侧任务树也没有管理入口，管理员只能在右侧工具栏新建任务，删除任务只能进入浮窗；成员个人页没有左侧任务树，管理员与成员在树操作上的权限差异无法体现。用户希望整个服务默认定时检测并自动保存，且自动保存可通过 `~/.ztask/settings.json` 或 `ztask` 命令关闭；同时希望管理员左树和成员个人页左树都能右键，管理员专属项在成员端置灰，并把「仅管理员」标签放到对应选项行，方便后续按项开放成员权限。

## Decision

在管理员事项跟踪、成员管理和成员视图顶栏统一放置自动保存状态：默认「自动保存 / 每 5 秒检测一次」，检测到编辑后「检测到变更 / 将在 5 秒内自动保存」，保存中「正在自动保存…」，完成后「已自动保存 / HH:MM:SS 已保存」，必填项缺失时「有未保存更改 / 补全必填项后自动保存」。点击状态条打开设置浮层，展示开关、`~/.ztask/settings.json` 的 `autosave.enabled` 示例和 `ztask autosave off` / `on` 命令；默认开启，配置缺失时按开启处理。关闭后状态条显示「自动保存已关闭」，任务/成员浮窗恢复「取消 / 保存」，成员视图进度恢复「保存进度」，关闭浮窗时若有手动修改先确认丢弃。

任务与成员编辑浮窗接入自动保存：已有对象在输入后自动写入原型内存并刷新树/卡片/表格，底部由「取消 / 保存」改为「更改会自动保存 / 完成」；新建任务和新建成员仍保留明确的「创建任务」或「添加」动作。成员视图的进度调整同样进入自动保存，手动「立即保存」保留为兜底；进展详情追加仍即时生效。

管理员左树和成员个人页左树都支持右键菜单。菜单项带 `requiresAdmin` 元数据；管理员看到可用操作，成员看到同一组操作但管理员专属项置灰，并在每个对应选项行显示「仅管理员」标签。右键任务夹显示「新建任务」和「新建子任务夹」；右键任务显示「新建任务」和「删除任务」。菜单头只显示当前目标，不再放权限标签；删除沿用确认弹窗。成员个人页左侧树包含团队当前全部可见任务及其上级目录；卡片维持「我负责 / 我协作 / 其他成员」三组、标题可折叠，点击任务夹只筛选卡片，不改变树的团队范围；成员树不提供任何实际写操作。

本次交付只更新静态原型、规格测试、评审截图和流程/决策记录，不修改真实 `apps/web`、服务端保存协议或 CLI 实现。

## 实现状态

树右键菜单已落到真实 `apps/web`：`FolderTreeNode` 向上发出菜单目标，`TrackerView` 渲染统一菜单并执行新建任务、新建子任务夹和删除任务；管理员操作可用，成员事项跟踪树保留同一组操作但置灰管理员专属项并逐行显示「仅管理员」。新增/删除复用现有任务编辑器、API 和确认弹窗。自动保存设置、`~/.ztask/settings.json` 读写和 `ztask autosave` 命令仍只在原型中，作为后续实现契约。

## Alternatives considered

未采用「成员端不显示右键菜单」的旧方案，因为用户希望成员能看到菜单并理解哪些操作暂不可用，也便于后续按项开放；未采用「在菜单头放一个仅管理员标签」的方案，因为无法区分单个选项，后续开放某项时标签会误导；未采用「关闭自动保存后仍然自动写内存」的做法，因为配置就失去意义；未采用「新建任务/成员也按定时器自动创建」的方案，因为必填项尚未完成时会生成半成品数据；未采用「成员树只显示与自己相关的任务」的方案，因为主分支已确认成员可查看团队全部任务，树需要与卡片范围一致；未采用「筛选后重置分组折叠」的方案，因为用户刚折叠的分组不应因选择任务夹而展开；未采用「只在任务夹右键菜单放删除任务夹」的方案，因为删除任务夹会级联影响任务，超出本次新建/删除任务的要求。

## Consequences

原型中的数据只保存在内存，刷新页面不会保留自动保存结果；设置开关不会真正读写 `~/.ztask/settings.json`，CLI 命令也只作为设计契约展示。真实实现仍需要服务端按版本冲突、权限和审计规则处理写入，并新增 settings 读取/写回与 `ztask autosave off|on|status` 命令；成员树与团队可见范围、分组折叠的交互、成员端可开放哪些操作，以及自动保存间隔是否也配置化，仍需在原型确认时决定。确认后再同步 `plan/fullstack-design` 和真实前端/CLI。
