P1 切换人员筛选会把已选时间段重置为“昨天至今”
P1

切换人员筛选会把已选时间段重置为“昨天至今”

实际
自定义 2026-11-04 后点击任一成员 chip，任务进展变化立即改发 mode=default；日期输入回退为 11-03→11-04，状态行变回“已自动查询 · 昨天至今”。
预期
保留已提交的自定义起止日期与日期控件，只在其中按成员收窄；周舟在今天无变化时应显示空态。
影响
筛选结果混入所选时间段之外的“区间内创建”记录（如 C 在 11-03 创建），用户会误判所选时间段内实际发生的进展。
根因
DashboardPanel 在 summaryQuery.isLoading 时用 LoadingState 替换整个内容区；成员变更触发 summary 新 query key 进入 loading，ChangesPanel 被卸载重挂，局部 submitted 状态回到默认。
修复
summaryQuery 增加 placeholderData: keepPreviousData，成员切换期间保留上一份 summary，内容区与 ChangesPanel 保持挂载；changes 查询继续使用已提交的 mode/startDate/endDate，并叠加新的 memberIds。
验证
真实构建 + 真实 API：前端 9 个 GUI 场景通过（自定义区间+成员筛选、空态、分布图、历史折叠、视图切换，无 console error）；后端 26 项 API 断言通过；新增组件用例修复前失败、修复后通过。
