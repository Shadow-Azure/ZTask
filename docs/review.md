# 评审规则

[English](review.en.md) | 中文

## 评审看什么

- 门禁全绿是底线不是终点：`pnpm verify:docs` 绿只说明机械规则过审，语义（口径漂移、边界扩张、术语混用）靠人。
- 文档改动：两侧是否同步、索引与预算是否登记、新术语是否先进词表。
- 门禁脚本改动：规则与文档是否两侧同步（改规则必须同时改 `docs/AGENTS.md` 等语义来源）、自测试是否覆盖新分支。
- 流程相关改动：流程树未初始化阶段，不引入 roadmap/milestone/issue 内容。

## 评审方式

- 小步 PR：一个 PR 一个语义，标题写清楚做了什么。
- 评审者先读 PR 模板的「取舍与影响」，再看 diff；对文档看「登记了没有」，对脚本看「绕过路径堵了没有」。
- 有争议的取舍写 Agent Note 引用进 PR，不留在评论区。

## 验收

- PR 模板勾选项全部落实；需要人工验收的步骤在 PR 描述里给出可执行命令与预期输出。
